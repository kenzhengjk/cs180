$$ H = \begin{bmatrix} h_1 & h_2 & h_3 \\ h_4 & h_5 & h_6 \\ h_7 & h_8 & h_9 \end{bmatrix}, \quad h_9 = 1 $$

We have eight unknowns so need at least four points to be able to solve the system!

def convolve_4loops(image, kernel, padding=True):
    if padding:
        pad_h, pad_w = kernel.shape[0] // 2, kernel.shape[1] // 2
        padded = np.pad(image, ((pad_h, pad_h), (pad_w, pad_w)), mode='constant')
    else:
        padded = image

    k_h, k_w = kernel.shape
    i_h, i_w = padded.shape
    output = np.zeros((i_h - k_h + 1, i_w - k_w + 1))

    for i in range(output.shape[0]):
        for j in range(output.shape[1]):
            for ki in range(k_h):
                for kj in range(k_w):
                    output[i, j] += padded[i + ki, j + kj] * kernel[ki, kj]

    return output

Runtime Comparison and Boundary Handling

The 4 loop convolution function runs in O(N^4) time (assuming worst case where kernel dimensions can get as large as image dimensions NxN) and the 2 loop convolution function runs in O(N^2) time, both significantly slower than scipy.signal.convolve2d. From empirical testing, 4 loop convolution took on average 154.15 seconds to convolve my selfie with the 9x9 box filter, 2 loop convolution took on average 11.98 seconds, while scipy.signal.convolve2d only took 0.44 seconds!

Boundary handling relates closely to padding. My implementations explicitly 0-pad if the pad argument is True. For scipy.signal.convolve2d, padding is controlled by the boundary argument: "fill" pads with a constant value (i.e., fillvalue), while "wrap" uses periodic and "symm" uses symmetric boundary conditions.
