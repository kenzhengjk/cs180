Final Results For Others Tweaks

At very low values for max position encoding frequency (e.g., L=1), the image becomes more and more smooth. This makes sense since the reconstruction mainly captures large-scale, global features of the image, ignoring sharp local details and high-frequency noise. As seen below, for very low L=1, the reconstruction resembles some abstract modern geometric art, while at L=5 we almost get a lightly Gaussian blurred version of the original.

At very low values of width (e.g., hidden_dim=4) we lose learning ability. Since width directly correlates with the number of parameters in our network, for very low width we underfit, as seen below, because we have limited representational capacity. The high bias of our hidden_dim=4 final result shows the network only learning the simplest global pattern (i.e., there's some entity with some background). Uping the width to 16 shows a big improvement, but it still fails to learn more intricate and complex features of the image, like whisker shape and individual fur colors.

Part 2: Fit a Neural Radiance Field from Multi-view Images

Brief Implementation Description

Part 2.1: Create Rays from Cameras

I implemented three functions for this part. All with pretty straightforward logic.

transform(c2w, x_c): converts 3D points from camera space to the world space using a homogeneous transformation.
pixel_to_camera(K, uv, s): converts pixel coordinates (u, v) with depth s to 3D camera coordinates. Here I extract intrinsic parameters from the camera matrix and use the pinhole camera inverse equations.
pixel_to_ray(K, c2w, uv): computes ray origins and directions in world coordinates for each pixel.

Part 2.2: Sampling

I followed the question set for this part and implemented one function for each of the two prompt paragraphs.

sample_rays_from_images_stratified(images, c2ws, K, n_rays, training=True): I opted for the first method of sampling rays. This function samples a fixed number of rays per image (instead of compressing and sampling globally). If the training flag is set to True, then it randomly selects n_rays_per_image pixels; else, it uniformly samples pixels.
sample_points_along_rays(ray_origins, ray_directions, near=2.0, far=6.0, n_samples=64, training=True): samples 3D points along each ray between the near and far planes (i.e., stratified sampling step for NeRF). If the training flag is set to True, it adds some random perturbation: np.random.rand(N_rays, n_samples) * ((far - near) / n_samples), applied within each interval to improve training robustness!

Part 2.3: Putting the Dataloading All Together

I implemented a dataloading class to preprocess and store all the data neatly.

class RaysData: precomputes all possible rays from (origins, directions) and corresponding pixel colors from the set of multiview images. It contains a private function _precompute_rays(self), which loops through each image, calls pixel_to_ray(K, c2w, uv) to acquire ray origins and directions in world coords. Then all image data is concatenated into numpy array of shape [N_images * H * W, 2]. The class also contains a public function sample_rays(self, n_rays), which randomly selects n_rays indices from all precomputed rays and returns the corresponding ray origins, directions, and pixels subsets.

Part 2.4: Neural Radiance Field

I implemented this part exactly following the description given and replicated the LEGO results shown. The same sinusoidal positional encoding is used now with two frequencies to capture both high and low frequency spatial details!

Positional Encoders: a position encoder (L=10) takes (low) 3 dimensional inputs to a (higher) 63 dimensional space. A direction encoder (L=4) takes 3 dimensional input to 27 dimensional space.
Network Architecture: num_layers = 8 (8 hidden layers with skip connection after layer 4), hidden_dim = 256 (width of hidden layers is 256)
Training: num_iterations = 1000, batch_size = 10000, n_samples = 64, learning_rate = 5e-4

Part 2.5: Volume Rendering

Following the given discrete approximation equation of the core volume rendering equation and the suggestion to use torch.cumprod, the core volrend function is birthed.

volrend(sigmas, rgbs, step_siz): computes volume rendering for each ray using the discrete approximation equation. Densities are first converted to per-sample opacities (alpha-compositing). Then transmittance is computed using exclusive cumulative product (torch.cumprod). Transmittances are then multiplied with their corresponding alphas to acquire weights. At last, the final color is rendered as a linear combination (i.e., weighted sum) of each color at sample i weighted by its weight!
